# UI設計

## 1. 設計方針

- Wordのページ構成をそのままGUIへ再現しない。入力しやすさ・キーボード操作性・誤入力の少なさを優先する（10.節、業務ツールとしての要求）。
- 主対象解像度 1920×1080、最低 1366×768 でも操作可能とする。
- 左ナビゲーション＋中央編集エリアの2ペイン構成を基本とする。

## 2. 全体レイアウト

```
┌────────────┬─────────────────────────────────────────────┐
│ プロジェクト │  [中央編集エリア：選択中の画面]                    │
│ 申請者       │                                             │
│ 装置概要     │                                             │
│ 動作モード   │                                             │
│ 機器リスト   │                                             │
│ ケーブル     │                                             │
│ 構成図       │                                             │
│ EMC対策      │                                             │
│ イミュニティ │                                             │
│ 医療規格     │                                             │
│ 台湾資料     │                                             │
│ 資料インポート│                                             │
│ 出力         │                                             │
└────────────┴─────────────────────────────────────────────┘
   [ステータスバー：保存状態 / 最終自動保存時刻 / エラーログ通知]
```

- 追加資料（イミュニティ／医療／台湾）はプロジェクトの選択フラグ（38.節）に応じて、ナビゲーション上でグレーアウトはせず常時アクセス可能にする（未選択でもデータ入力自体は妨げない。Word出力時にのみフラグで出力要否を判定する）。
- Ctrl+S＝保存、Ctrl+Z/Ctrl+Y＝Undo/Redo（構成図編集中）、Tab移動でフォーム間を素早く移動できるようにする（10.節：キーボード操作しやすさ優先）。

## 3. 機器リスト画面（Equipment）

### 3.1 一覧表示

```
┌───────────────────────────────────────────────────────────┐
│ カテゴリ: [EUT ▼]        [+ 新規機器]  [インポートから追加]      │
├───┬──────────┬───────────┬────────┬──────────┬───────────┤
│ ID │ 機器名     │ モデル名     │ シリアル │ 配置       │ 操作       │
├───┼──────────┼───────────┼────────┼──────────┼───────────┤
│ A │ EUT本体    │ ABC-100    │ SN001  │ 独立       │ [編集][削除]│
│ B │ SDカード    │ SD-16GB    │ -      │ ⤷ A に内蔵 │ [編集][削除]│
```

内包機器は親の直下にインデント表示し、「⤷ A に内蔵」のように親のdisplay_idを明示する。カテゴリタブ（EUT / Peripheral / Associated Equipment / Other）で絞り込み可能。

- 「独立機器」選択時、親機器コンボボックスは非活性（disabled）になり値もクリアされる。

- 保存時、Service層の循環参照チェックに引っかかった場合はダイアログを閉じずにエラーメッセージを表示する。

## 4. ケーブルリスト画面（Cable）

```
┌────────────────────────────────────────────────────────────────┐
│ [+ 新規ケーブル]                                                    │
├────┬──────┬──────┬──────┬──────┬────────┬──────┬────────┤
│ No. │ From  │ To    │ 種類   │ 長さ   │ Shield  │ 上限長  │ 屋外接続 │
├────┼──────┼──────┼──────┼──────┼────────┼──────┼────────┤
│ 1  │ A:USB │ C:USB │ USB   │ 1.5m  │ Shielded│ 5m以下  │ しない   │
│ 2  │ B:VGA │ A:VGA │ VGA   │ 1.5m  │ Non     │ -      │ しない   │
└────┴──────┴──────┴──────┴──────┴────────┴──────┴────────┘
```

- From/Toはプルダウンで機器一覧（内包機器も含む、20.節）から選択。表示は「表示ID:機器名」、内部的には`equipment_id`を保持。
- 行インライン編集（テーブルセルを直接クリックして編集）を基本とし、ダイアログを開かせない（測定担当者の入力速度優先）。
- ケーブル種類選択時、`docs/word-template-analysis.md` 7.節の参考上限長（USB 5m、LAN 100m等）をプレースホルダ/ツールチップとして表示し、`maximum_length`欄の入力補助にする（必須の自動入力ではなく、あくまで参考表示）。
- 行の右クリックメニューから「InlineComponent（フェライト等）を追加」を選べる。選択すると同一画面下部に選択中ケーブルのInlineComponent一覧が展開表示される。

## 5. Containment設定（機器編集ダイアログに統合）

内包関係専用の別画面は設けず、3.2の機器編集ダイアログ内に統合する（4.節・17.節）。ただし機器リスト画面のツリー表示（3.1）自体がContainment全体の一覧性を兼ねる。

親子関係の一括確認用に、機器リスト画面に「ツリー表示 / フラット表示」切り替えトグルを設ける。

## 6. 接続情報画面（Connection）

ケーブルリスト画面（4.節）がFrom/Toを直接保持するため、独立した「接続情報」専用画面は設けない。**ユーザー確認済み**：ケーブルリストのFrom/Toだけで構成図の生成・表示に問題は無いため、左ナビゲーションから「接続情報」項目自体を削除した（Phase 4実装時）。ケーブルリスト画面と構成図画面が接続情報の入力・可視化を兼ねる。データモデル上の概念的な分離（Containment/Connection/Cableを混同しない）は`docs/data-model.md`の通り維持する。

## 7. 構成図Editor

### 7.1 画面構成

```
┌─────────────────────────────────────────────────────────────┐
│ [自動配置] [Undo][Redo] [ズーム-][100%][ズーム+][Fit] [PNG書出]  │
├─────────────────────────────────────────────────┬─────────┤
│                                                     │ プロパティ │
│      ┌─────────────┐        ┌───────────┐    │ パネル     │
│      │ A EUT        │────2───│ C Monitor  │    │           │
│      │  ┌─────────┐ │  VGA   └───────────┘    │ 選択中:    │
│      │  │ B SDCard│ │                            │ Node A    │
│      │  └─────────┘ │        ○AC100V             │ X:120     │
│      └─────────────┘            │                 │ Y:80      │
│                                   │                 │ W:160    │
│                                  ⏚ FG               │ H:100    │
│                                                     │           │
└─────────────────────────────────────────────────┴─────────┘
```

- 中央：`QGraphicsView` / `QGraphicsScene`。
- 右：選択中Node/Edgeのプロパティ（座標・サイズ・ラベルオフセット）を数値入力でも微調整できるようにする（ドラッグ操作が苦手なユーザー向け、10.節「間違いにくい」への対応）。

### 7.2 Node表現

- Equipment：四角形。内部に `表示ID` + `機器名`（29.節の表示例：`A` / `A EUT` / `A 機器名称`を機器のカテゴリ・スペースに応じて自動選択、手動で表示内容を切り替え可能）。
- PowerSource：丸形（22.節）。
- GroundConnection：接地記号（23.節、一般的なアース記号を描画）。
- 内包Equipment（子Node）：親Node内部に描画し、親の枠外へドラッグで出せないようクランプする（25.節）。ドラッグ中、親の境界に近づくと吸着ガイドラインを表示する。

### 7.3 Cable（Edge）表現

- 直線、または中間点を挟んだ複数の直線区間（折れ線）を組み合わせて描画する（30.節）。**曲線（ベジェ曲線等）は採用しない**：他の図形と重なりそうな場合に鋭角で迂回させたいという要求のため、常に直線の組み合わせのみとする。線を右クリックすると「ここに中間点を追加」「この中間点を削除」を選択でき、既存の中間点はドラッグで移動できる。実装済み（`diagram/items/cable_item.py`）。
- 線の近傍に `Cable No.` / `Cable Type` / `Port Name` をラベルとして表示。InlineComponentが登録されていれば `[F1]` のような略記、またはホバーで詳細ツールチップ（フェライト種類・型式）を表示する。

### 7.4 操作一覧（31.節準拠）

| 操作 | 方法 |
|---|---|
| Node選択 | クリック |
| 複数選択 | Shift+クリック、またはラバーバンド矩形選択 |
| Node移動 | ドラッグ（子Nodeは親内部にクランプ） |
| Nodeサイズ変更 | 選択時のハンドルドラッグ、またはプロパティパネルで数値入力 |
| Cable追加 | ツールバー「線を追加」→ From Node → To Node の順にクリック |
| Cable削除 | 選択してDeleteキー、または右クリックメニュー |
| 線ルート変更 | 中間点をドラッグ／右クリックで中間点追加・削除 |
| ラベル位置変更 | ラベルをドラッグ（Node/Edge本体とは独立して移動） |
| Undo/Redo | Ctrl+Z / Ctrl+Y、ツールバーボタン |
| ズーム | ツールバー、Ctrl+ホイール |
| Fit to View | ツールバーボタン、ショートカット `F` |
| 自動配置 | ツールバー「自動配置」ボタン（32.節のルールで再配置、確認ダイアログの上で既存の手動調整を上書きする旨を警告） |

### 7.5 自動配置ルール（32.節）

初期配置ロジック：
- EUT categoryのEquipment → キャンバス中央
- Peripheral → 左または下
- AssociatedEquipment → 右
- PowerSource → 上
- GroundConnection → 下
- 内包Equipment → 親Nodeの内部（親のサイズに応じて自動的にグリッド配置）

自動配置は「一度だけ実行して後は手動調整」という運用を前提とし（32.節「完全自動配置だけに依存しない」）、実行後はUndo可能な1つの操作としてまとめて記録する。

## 7A. 自由記述系画面（動作モード・EMC対策・イミュニティ・医療規格・台湾資料）

**ユーザー確認済み**：これらの画面は文章量が多くなりやすいため、構造化された細かい入力欄よりも自由記述（フリーライティング）を優先し、テキストエリアは大きく（最低でも140〜180px程度の高さ）確保する。

- **動作モード／EMC対策**：カード形式の繰り返しリスト（+追加ボタンで複数件登録可能）。各カードは短い識別項目（モード名、または対策部品のモデル名・メーカー名）を上部に置き、その下に大きな自由記述欄を配置する。EMC対策のモデル名・メーカー名は現行Word帳票の注記により必須記入項目として明示する。
- **イミュニティ**：Performance Criterion A/B/Cをそれぞれ独立した大きなテキストエリアとする（Word帳票側が3つの別セルのため）。動作確認箇所は1行1項目の自由記述欄とし、保存時に改行で分割してリストとして保持する。
- **医療規格**：基礎安全／基本性能の判定基準をそれぞれ1行1項目の自由記述欄、イミュニティ試験時の性能基準を1つの大きなテキストエリアとする。
- **台湾資料**：申請者情報（会社名・住所の英語／繁体字）は短い入力欄のまま、EUTの内部構成品リストは表形式（装置名／数量／モデル名／製造者、機器リストと同様のテーブルUI）、試験時のEUT動作状態は大きな自由記述欄とする。

## 8. Import確認画面

```
┌───────────────────┬──────────────────────────────────┐
│ 顧客資料            │ 認識結果                            │
│                    │                                    │
│ [ファイル選択/D&D]   │ Equipment候補                       │
│                    │  ☑ EUT           [High]             │
│  例) 顧客Excel.xlsx │  ☑ PC            [High]             │
│                    │  ☑ Monitor       [Medium]           │
│                    │  ⚠ 不明な機器行3   [Low]  [編集][除外]  │
│                    │                                    │
│                    │ Cable候補                            │
│                    │  ☑ EUT-PC USB    [High]             │
│                    │  ⚠ Unknown Cable [Low]  [編集][除外]  │
│                    │                                    │
│                    │        [取り込む]   [キャンセル]        │
└───────────────────┴──────────────────────────────────┘
```

- 信頼度（High/Medium/Low）をバッジ表示。Lowは背景色で強調し目立たせる（46.節）。
- 各候補行は取り込み前にインライン編集可能（誤認識の修正）。
- 「取り込む」ボタン押下時のみ実際のEquipment/Cableテーブルへ確定登録する。それまではメモリ上（または`import_candidates`テーブルへの一時保存）に留める（45.節）。
- 顧客ごとのマッピングが既知の場合、画面上部に「ImportProfile: [顧客A ▼]」を表示し、選択すると項目名マッピングが自動適用された状態で候補が表示される（47.節）。

## 10. エラー表示（60.節）

- 例外発生時は共通のトースト通知／モーダルで「処理中にエラーが発生しました。詳細はログを確認してください。」を表示。
- ステータスバーに「ログを開く」リンクを常設し、`logs/app.log`を既定のテキストエディタで開けるようにする。

## 11. アクセシビリティ・キーボード操作

- 全編集画面はTabキーでフィールド間移動可能、Enterで次フィールドへ（多段入力を素早く行うため）。
- 一覧画面（機器・ケーブル）は矢印キーで行移動、Enterで編集モードに入れるようにする（Excel的操作感、測定担当者の慣れを考慮）。
- 構成図Editorのみマウス操作中心だが、選択中Nodeの微調整は矢印キーで1pxずつ移動できるようにする（Shift+矢印で10px移動）。
